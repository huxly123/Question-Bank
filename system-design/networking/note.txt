1. How the Web Works
     
    When a user enters a URL, the browser first performs a DNS lookup to convert the domain name into an IP address.
    Then it establishes a TCP connection with the server and performs a TLS handshake if HTTPS is used. The browser sends 
    an HTTP request to the server. The server processes the request and returns an HTTP response containing HTML, CSS, or JavaScript. 
    The browser then parses these resources, builds the DOM and CSSOM, creates a render tree, performs layout and paint, and finally 
    displays the webpage.

    URL entered
        ↓
    DNS lookup
        ↓
    TCP + TLS connection
        ↓
    HTTP request
        ↓
    Server processing
        ↓
    HTTP response
        ↓
    Browser rendering

2. Rest API's
   
   REST APIs are a way for clients and servers to communicate using HTTP. In REST, everything is treated as a resource identified by a URL.
   Clients perform operations on these resources using standard HTTP methods like GET, POST, PUT, and DELETE. REST APIs are stateless, meaning 
   each request contains all the information required to process it. Responses are usually returned in JSON format.

3. Graphql

   GraphQL is a query language for APIs that allows clients to request exactly the data they need. Unlike REST APIs which expose multiple endpoints, 
   GraphQL uses a single endpoint where clients send queries specifying the required fields. This helps avoid over-fetching and under-fetching of data. 
   GraphQL APIs define a schema and use resolvers to fetch data from databases or services.

4. REST vs Graphql

   REST and GraphQL are both API communication styles. REST uses multiple endpoints with fixed response structures, while GraphQL uses a single endpoint 
   where the client specifies the exact data required. REST is simpler and works well with HTTP caching, while GraphQL provides more flexibility and avoids 
   over-fetching or under-fetching of data. However, GraphQL adds backend complexity and requires additional caching strategies.

5. gRPC
   
   gRPC is a high-performance RPC framework developed by Google. It allows clients to call methods on remote servers as if they were local functions. 
   gRPC uses HTTP/2 for transport and Protocol Buffers for efficient binary data serialization, making it faster than traditional REST APIs. 
   It also supports streaming communication and is widely used for communication between microservices in distributed systems.

6. CDN (Content Delivery Network)

    A CDN stores cached copies of static content in servers located around the world.
    Instead of requesting files from the origin server, the browser gets them from the nearest CDN server.

7. Load Balancer

    A Load Balancer distributes incoming traffic across multiple servers.
    Instead of all users hitting one server, traffic is distributed evenly.

    Why it is needed:

    If one server receives too many requests, it can crash.
    A load balancer prevents this by spreading traffic.

8. API Gateway

    An API Gateway is a centralized entry point for all client requests in a microservices architecture. Instead of the client directly 
    calling multiple backend services, it sends requests to the API Gateway, which routes them to the appropriate service. It also handles 
    cross-cutting concerns like authentication, rate limiting, request aggregation, and logging. This simplifies client communication and 
    improves security and scalability.
